## Ranked gaps / remaining risks

1. **Major visual acceptance risk, ANIM-02/14:** candidate14 M1911 slide-release evidence still puts the support sleeve/glove across much of the action. See `target/playtest/animations-ads-candidate-14/dual/m1911-slide-release.png` and `dual/movement-review/m1911-slide-release-adjacent.png`, real samples 439–445, approximately 17.299–17.518 s. The mechanism changes mathematically, but this image sequence does not establish a clearly readable slide manipulation. MP5 release likewise needs normal-speed review, not a scalar `bolt`/`latch` log. This is a concrete framing concern, not a claim that every release frame is defective or that a unit test can adjudicate art. No implementation change is requested during the active pipeline.
2. **Completion blocker by design, ANIM-11:** final frozen gates, healthy physical matrix, single/dual no-video runs, camera-matched before/after costs and isolated sensor remain unreviewed. Candidate14 is useful intermediate evidence, not evidence for the latest extra wood regression or a final performance conclusion. Do not infer pipeline results from this report. The spec does not quantify an acceptable relative frame/tick regression; preserve the absolute existing <7.8 ms load bound and disclose relative changes rather than silently choosing a threshold.
3. **Quantitative coverage gap, ANIM-06:** native assertions prove snapshot-loss execution, persistent IDs, recovery state and final convergence; they do not directly bound displayed remote root/limb transform deltas, interpolation error or finite rotations during missing snapshots. `client/src/render/actors.rs:485–495,591–608,899–904` implement easing/extrapolation caps, but source arithmetic is not an assertion. `actors.rs:1019–1025` asserts entity IDs, not smooth pose. The spec also leaves “bounded interpolation” without a numerical tolerance. Final report must keep that distinction, backed by actual frame review or a focused quantitative loss test/accepted bound.
4. **Contact coverage limits, ANIM-01/02/03/14:** the composed real-assembly test is substantially stronger than helper-only tests, but asserts cuff-to-glove wrist and elbow continuity, not actual finger/palm-to-magazine/slide/handle surface contact, occlusion or clipping. `feedback.rs:614,619,631` do not prove those other outcomes. It samples five empty-reload fractions and three ADS weights, not continuous tactical/interrupted actions, camera pitch/roll or all aspect ratios. Shared remote anchor tests omit the actual renderer's recoil modification. Treat the remaining dimensions as visual/evidence work, not a demonstrated code defect.
5. **Narrower-than-worded automated assertions, ANIM-07/08/09:** corpse construction tests prove supplied per-segment transforms/velocities are used exactly; capture integration proves root/articulated movement is nonzero, but does not compare every captured finite-difference velocity to an independently calculated expectation. Force tests compare opposite application sides for one impulse and conserve its vector; they do not directly pair opposite force directions/intensities with otherwise identical setup. The eight-case rest test checks final 8 s state, not joint angles/contact events/bounds throughout every intermediate tick. Running cases do demonstrate obstacle-dependent displacement. Do not describe these as exhaustive trajectory or anatomical-quality certification.
6. **Minor documentation drift, ANIM-11/12:** `design.md:17` still says protocol4 and 59,528 bytes; current `common/src/lib.rs:14` is protocol5 and candidate14 measured 59,784 bytes. `docs/ANIMATION_RAGDOLL.md`/tasks/guide contain clearly historical and stale latest-candidate/count paragraphs. Their cautious “in progress” wording is correct, but final evidence links, protocol/current counts and reviewed limits need reconciliation after the pipeline. Mermaid fall/recovery/death/ADS paths were reviewed statically; no diagram parser was run.
